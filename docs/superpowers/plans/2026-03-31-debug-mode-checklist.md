# 디버그 모드 세션 체크리스트 (Cursor / 런타임 증거)

에이전트가 **코드만 보고 추측 수정하지 않도록** 묶는 절차입니다.  
(프로젝트 스킬: `.cursor/skills/systematic-debugging/SKILL.md` — Phase 1~4와 함께 쓰면 좋음.)

---

## 0. 세션 시작 시 기록할 값 (시스템이 주면 복사)

다음은 **세션마다 바뀔 수 있음**. 이번 디버그에 쓸 값을 한곳에 적어 둔다.

| 항목 | 용도 |
|------|------|
| **Server endpoint** | JS/TS 등에서 `fetch` POST로 전송 시 |
| **Log path** (예: `debug-ab4bf2.log`) | C++ 등은 **워크스페이스 루트**에 NDJSON append |
| **Session ID** | 페이로드 `sessionId`, 헤더 `X-Debug-Session-Id` (비어 있으면 생략) |

**C++ 로그 파일 경로 예:** `FPaths::ProjectDir() / TEXT("../debug-<session>.log")` — `.uproject`가 `DH1_Client` 아래일 때 저장소 루트와 맞춤.

---

## 1. 가설 (Phase 1 — 수정 전)

- [ ] **가설 3~5개**를 문장으로 적는다 (왜 버그가 날 수 있는지, 서브시스템/스레드/패킷 경로 등).
- [ ] 각 가설에 **ID**를 붙인다 (`H1`, `H2`, …). 이후 계측·로그 분석에서 동일 ID로 묶는다.

---

## 2. 계측 (Instrumentation)

- [ ] 가설마다 **최소 1줄 이상** 런타임 로그가 나가게 한다 (보통 **2~6개**면 충분, 최대 10개).
- [ ] 페이로드에 **`hypothesisId`**, **`location`**, **`message`**, **`timestamp`**, 필요 시 **`data`** 포함.
- [ ] **NDJSON** 한 줄 = JSON 객체 하나 (C++는 `FFileHelper::SaveStringToFile` + `FILEWRITE_Append` 등).
- [ ] 계측 블록은 **`// #region agent log` ~ `// #endregion`** (또는 언어별 동등물)로 감싼다.
- [ ] **금지:** 토큰, 비밀번호, API 키, 개인정보 로깅.

---

## 3. 실행 전 로그 정리

- [ ] **이번 세션 로그 파일만** 삭제한다 (`delete_file` 도구 — **다른 세션 ID 로그는 건드리지 않음**).
- [ ] 셸의 `rm` / `touch` 등으로 로그를 지우지 않는다.

---

## 4. 빌드·실행 (에이전트가 직접)

- [ ] 변경 후 **관련 타깃 빌드**를 돌리고, 성공/실패를 확인한다 (예: `DH1_ClientEditor` Win64 Development).
- [ ] 서버 이슈면 **World/Gateway 등** 해당 바이너리도 재빌드·재기동이 필요한지 적어 둔다.

---

## 5. 재현

- [ ] 사용자에게 **번호 목록** 재현 절차를 준다 (인터페이스에 따라 “Proceed / Mark as fixed” 안내는 시스템 규칙에 맞게).
- [ ] 필요 시 **서버·클라 재시작**을 재현 단계에 명시한다.

---

## 6. 로그 분석 (수정 전)

- [ ] **Log path**에서 NDJSON을 읽는다.
- [ ] 가설별로 **CONFIRMED / REJECTED / INCONCLUSIVE**를 **로그 인용**과 함께 적는다.
- [ ] 로그가 비어 있으면 재현 실패 가능성을 알리고 **다시 재현**한다.

---

## 7. 수정

- [ ] **로그로 입증된 원인**에만 최소 수정을 한다.
- [ ] 로그가 **기각한 가설**용으로 넣었던 **방어 코드·추측 가드**는 되돌린다 (불필요 누적 금지).
- [ ] **계측은 아직 제거하지 않는다** (검증 끝나기 전까지).

---

## 8. 검증 (post-fix)

- [ ] 실행 전 다시 **세션 로그 파일만** 삭제한다.
- [ ] 동일 재현으로 한 번 더 돌린 뒤, **before/after 로그**를 인용해 비교한다.
- [ ] 검증용 로그에는 필요 시 `runId: "post-fix"` 등으로 구분한다.

---

## 9. 계측 제거 조건

- [ ] **post-fix 로그로 성공이 입증**되고, 사용자가 **이상 없음**을 확인한 뒤에만 `#region agent log` 블록을 제거한다.
- [ ] 사용자가 **계측만 당장 빼 달라**고 하면 그때 제거해도 됨.

---

## 10. 금지 사항 (디버그 모드)

- [ ] `setTimeout` / `sleep` 등 **인위적 지연**을 “수정”으로 쓰지 않는다.
- [ ] 런타임 증거 없이 **100% 확신**처럼 고치지 않는다.

---

## 11. 이 레포 수동 검증 예시 (맥락별로 복사해 사용)

**AOI / 원격 엔터티**

- [ ] 클라 A·B 동시 접속, 같은 AOI에서 **ENTER** 후 상대 프록시(또는 로그) 확인.
- [ ] 한쪽이 멀리 가면 상대에게 **LEAVE** 대칭 여부.
- [ ] 셀 경계 왕복 시 크래시·중복 ENTER/LEAVE 멱등성.

**채팅 UI (콤보 등)**

- [ ] 드롭다운 항목 **패딩·가독성** 스크린샷 또는 실기 확인.
- [ ] 채널 전환·전송이 프로토/게이트웨이와 일치하는지.
