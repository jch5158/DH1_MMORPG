# 로그인 체크박스(✓) + 채팅 전송/로그 설계

## Overview

1. **이메일 저장 체크박스**: 사용자 선택 **A안** — **둥근 사각형(22×22 근처)** 유지, **체크 시 안에 전형적인 ✓ 마크**가 보이도록 한다. `FCoreStyle` 체크박스 의존은 사용하지 않는다(기존 `RememberEmailCheckBoxStyle` 방침 유지).

2. **채팅**: 클라이언트는 전송 직후 **낙관적 UI**로 자신의 채팅 줄을 붙일 수 있으나, 게이트웨이에서 패킷이 거절되면 **타 클라이언트에는 전달되지 않고**, `HANDLE_C2S_CHAT_REQ`에 도달하지 못해 **Gateway/World `[CHAT]` 로그도 없을 수 있다.** 본 스펙은 그 원인을 **관측 가능**하게 하고, 제품 정책에 맞게 **검증 조건 또는 클라 가드**를 정리한다.

---

## 1. 체크박스 시각 (A안)

### 요구사항

- **미체크**: 테두리 있는 둥근 사각형 배경(현재 다크 톤·보더 컬러 계열 유지).
- **체크됨**(및 호버/프레스 변형): 동일한 박스 느낌 위에 **명확한 ✓** 가 보일 것.
- 크기: 기존과 같이 **약 22×22** 슬롯에 맞출 것.

### 구현 원칙

- `FCheckBoxStyle`의 **상태별 브러시는 각각 하나**이므로, “박스 + ✓”를 **한 장의 이미지**로 합치거나, 엔진/프로젝트에서 지원하는 방식으로 **단일 브러시에 합성된 결과**를 쓴다.
- **권장**: `Content`에 **체크 전용 소형 텍스처**(예: 투명 배경에 밝은 ✓ + 필요 시 박스 테두리)를 추가하고, **Checked / CheckedHovered / CheckedPressed** 브러시는 `ESlateBrushDrawType::Image` + `UTexture2D` 리소스로 지정한다. **Unchecked** 계열은 기존처럼 `RoundedBox` 벡터 브러시를 유지해도 되며, 이때 **모서리 반경·크기**가 체크 이미지와 시각적으로 맞도록 조정한다.
- 대안(텍스처 추가가 어려울 때): 동일 요구를 만족하는 **단일 합성 텍스처**만으로 Checked 계열을 통일한다(문서화된 에셋 경로).

### 파일

- 주 변경: `DH1_Client/Source/DH1_Client/UI/AuthWidgetStyle.h` (`RememberEmailCheckBoxStyle`).
- 신규 에셋(권장): `DH1_Client/Content/...` 아래 import된 `UTexture2D` (정확 경로는 구현 시 한 곳에 상수/문서로 고정).

### 범위 밖

- 다른 화면 전역 체크박스 테마 변경.
- UMG 전용 위젯으로 로그인 패널 전체 교체.

## 2. 채팅: 증상 2·3와 게이트웨이 검증

### 관찰된 연관

- 게이트웨이 `ChatPacketHandler::HandlePacket`은 `Validate()` 실패 시 핸들러 본문을 호출하지 않는다 → **릴레이 없음**, **`[CHAT] Gateway relayed...` 로그 없음**.
- `Validate`는 `IsLoggedIn() && IsInWorld()`이며, `ClientSession::IsInWorld()`는 **`mWorldServerId != 0`** 으로 정의된다.
- 클라 `SendChatRequest` 성공 후 **로컬 줄 추가**는 **서버 수신 여부와 무관**할 수 있어, **2번(남에게 안 보임) + 3번(서버 로그 없음)** 이 동시에 나타날 수 있다.

### 요구사항 (관측)

- 게이트웨이에서 채팅 패킷이 **Validate에서 막힌 경우**, 원인 판별을 위해 **WARN(또는 INFO) 로그를 한 줄** 남긴다. 예: `accountId`, `loggedIn`, `inWorld`, `worldServerId` (민감 필드 제외).
- 로그 메시지는 검색하기 쉬운 접두사를 유지한다(예: `[CHAT]`).

### 요구사항 (동작 — 확정 전 분기)

로그로 원인이 **`!IsInWorld()`** 로 좁혀지면, 제품 의도에 따라 아래 중 **하나**를 택한다.

| ID | 정책 | 조치 요약 |
|----|------|-----------|
| **B1** | 월드 진입 완료 후에만 채팅 허용 | 클라이언트에서 `SendChatRequest` / 채팅 UI 활성 조건을 **서버 “인 월드”와 정렬**하거나, 전송 전 **세션 상태**를 검사해 비활성·토스트 처리. 게이트웨이 Validate는 유지. |
| **B2** | 로비/비월드에서도 채팅 허용 | 게이트웨이 `ChatPacketHandler::Validate` 조건 완화(및 필요 시 월드 릴레이 대체 경로 설계). **스팸·저장 정책** 별도 검토. |

본 스펙 승인 시점에는 **B1/B2 중 최종 선택을 구현 플랜 전에 제품 결정**으로 남긴다. 기본 권장은 **원인 로그 추가 후 B1 여부를 데이터로 결정**하는 것이다.

### 성공 기준

- 정상 월드 플레이 중: 게이트웨이에 `[CHAT]` 릴레이 로그, 월드에 `[CHAT]` 처리 로그가 남고, **동일 AOI/채널 조건**을 만족하는 다른 클라이언트가 `S2C_CHAT_NOT`를 수신한다(기존 월드 브로드캐스트 규칙 준수).

### 파일 (예상)

- `DH1_Server/GatewayServer/PacketHandler/ChatPacketHandler.cpp` — Validate 실패 로그(및 B2 시 Validate 변경).
- (B1 시) `DH1_Client/Source/DH1_Client/Network/Subsystem/ClientNetSubsystem.cpp` 또는 채팅 UI 등록 경로 — 전송 가드.

## 3. 테스트 시나리오

### 체크박스

1. 미체크: ✓ 없음, 박스만 보임.
2. 체크: ✓가 명확히 보이고, 호버/프레스에서 깨지지 않음.
3. DPI/해상도에서 22×22 슬롯이 과도하게 깨지지 않음.

### 채팅

1. 월드 진입 후 전송: Gateway·World `[CHAT]` 로그 존재, 다른 클라 수신(해당 채널/거리 조건 만족 시).
2. (가능하면) 월드 진입 전·`worldServerId` 미설정 상태에서 전송: **새 WARN 로그**로 거절 원인 확인, 낙관적 UI만 있는 경우와 구분 가능.
